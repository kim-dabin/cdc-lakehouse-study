# 아키텍처 그림 검증 — 2026-10-14

`bahayonghang/drawio-skills`의 drawio 2.8.0 스킬을 설치하고 YAML → draw.io → Desktop PNG 절차로 세 그림을 작성했다. 설치 위치는 강사 컴퓨터의 `~/.codex/skills/drawio`다.

## 결과

| 그림 | PNG 크기 | 원본의 연결선 | 검증 |
|---|---|---:|---|
| 데이터 흐름 | 4772 × 3169 | 9 | 통과 |
| 저장·메타데이터 관계 | 4244 × 2944 | 6 | 통과 |
| 실행 환경 | 5088 × 3769 | 6 | 통과 |

- 각 `.drawio`를 스킬 CLI의 `--validate --strict`로 검사했다. XML 오류, 도형을 가로지르는 연결선, 연결선끼리의 교차는 각각 0건이었다.
- 설명이 14자를 넘는다는 정보성 알림은 의미를 보존하기 위해 유지했다. 경고 등급의 배치·연결·텍스트 검증 항목은 모두 해소했다.
- 모든 연결선은 source/target 도형 ID를 참조한다. 페이지 전체를 한 장의 이미지로 넣은 원본이 아니다.
- 2000px 이하 Desktop 미리보기와 최종 PNG를 직접 확인했다. 한글, 화살표, 설명 위치, 페이지 경계에 잘림이나 겹침이 없는지 점검했다.
- 초기 그림에서 구역 제목을 통과하는 선과 도형 위에 걸린 연결 설명을 발견해 수정했다.
- 최종 PNG의 헤더, chunk 길이와 checksum, 종료 chunk를 확인했다. PNG는 강의용 이미지이며 편집은 별도 `.drawio` 원본을 사용한다.

## 표현 범위

- 데이터 흐름 그림의 Bronze·Silver·Gold는 논리적인 테이블 계층이다.
- 저장 관계 그림의 화살표는 엔진의 접근 요청 방향이다. JDBC Catalog의 위치 관리와 MinIO의 파일 저장을 구분했다.
- 실행 환경 그림은 한 대의 맥미니 안에 있는 macOS 호스트와 Lima VM 영역을 구분한다. 한 개의 Docker Engine에 여러 컨테이너가 배치되는 구조다.
- dbt는 Spark Thrift에 SQL 실행을 요청하며 직접 객체 저장소에 접근하는 엔진으로 표현하지 않았다.
- 1회차 강사 시연·학생 SQL 작성 방식과, Airflow를 이후 회차에서 사용하는 계획을 반영했다.

이 작업은 설정과 수업 자료의 아키텍처 표현을 수정한 것이다. 데이터 파이프라인을 새로 기동하거나 런타임 상태를 검증한 결과로 해석하지 않는다. 기존 실행 리허설 결과는 [1회차 기록](../../labs/session01/rehearsal.md)에 있다.

작업용 YAML, sidecar와 검토 기록은 강사 워크스페이스의 `.drawio-tmp/architecture-v2/`에 보관한다. 배포 폴더에는 PNG와 편집 원본, 설명·검증 문서를 제공한다.

## 2026-10-17 검토 반영

01 그림의 이전 마트 수치와 1회차 수동 갱신 표기를 수정했다. 03 그림은 맥미니 코드 동기화와 호스트 loopback·Lima UI 경로를 구분했다. YAML 재생성·XML 검사·Desktop PNG 내보내기와 시각 점검을 수행했다. 노드 교차와 연결선 교차는 0이다. 편집 연결선의 모서리 슬롯에 대한 형식 경고가 남지만 분리된 두 수직 경로를 유지하기 위한 배치이며, 미확인 런타임 관계를 추가한 것은 아니다. 원본 PNG와 편집용 draw.io를 함께 제공한다.

이번 수정본의 재생성용 YAML은 `specs/`에 함께 보관한다. 이전 작업 임시 경로에 의존하지 않고 세 관점의 원본 명세를 확인할 수 있다.
