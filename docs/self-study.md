# 개인 환경에서 공통 예제 확인하기

공통 환불의 생성·정정·삭제를 개인 Docker 환경에서 실행하고, 원천·Kafka·Bronze·실제 Parquet에 무엇이 남았는지 대조하는 도우미입니다. 수업에서 명령을 많이 실행하기 위한 자료가 아니라, 설계하면서 궁금해진 동작을 다시 확인하는 경로입니다.

## 실행 전에

처음 받는 경우 저장소를 clone하고 해당 폴더로 이동합니다.

```bash
git clone https://github.com/kim-dabin/cdc-lakehouse-study.git
cd cdc-lakehouse-study
```

이미 clone한 저장소가 있다면 그 폴더에서 최신 자료를 확인합니다. 아래 명령은 **개인 컴퓨터의 저장소 루트**에서 실행합니다. 강사 맥미니에 접속하거나 강사 설정을 복사하지 않습니다. Bash, Python 3.9 이상, Docker Engine과 Docker Compose v2가 필요합니다. 기준은 Linux ARM64 컨테이너이며 다른 CPU의 이미지 호환성과 실행 성능은 별도 확인이 필요합니다. 첫 build에는 네트워크와 충분한 Docker 메모리·디스크가 필요합니다. [환경 운영 안내](operations.md)도 함께 봅니다.

실행 확인에 사용한 기준 환경은 **Linux ARM64 Docker VM, CPU 6개·RAM 10 GiB**입니다. 최소 사양이나 성능 보장 수치는 아닙니다. 개인 환경의 자원과 다른 작업의 사용량에 따라 실행 시간과 여유 공간이 달라집니다.

2026-10-23에는 기존 기동 환경의 `reuse`와 `--with-marts` 조합, 3회차 읽기 도우미를 실제 실행해 확인했습니다. **이번 확인에 최초 새 설치(`first`)의 전체 실행은 포함하지 않았습니다.** 기존 환경에서 확인한 결과를 모든 새 설치 환경의 실행 보장으로 확대하지 않습니다.

먼저 실행할 일을 읽어보세요. 다음 명령은 Docker에 접속하거나 파일·데이터를 만들지 않습니다.

```bash
./scripts/self-study.sh --plan
```

이후 **현재 환경에 맞는 한 가지**를 고릅니다. 세 명령을 차례로 실행하는 절차가 아닙니다.

| 내 상태 | 실행 | 목적 |
|---|---|---|
| 처음 설치하는 환경 | `./scripts/self-study.sh --environment first` | 필요한 환경 파일이 없을 때만 준비하고 기본 build로 기동 |
| 준비해 둔 프로젝트가 중지됨 | `./scripts/self-study.sh --environment start` | 기존 로컬 이미지를 사용해 다시 기동 |
| 필요한 서비스가 이미 실행 중 | `./scripts/self-study.sh --environment reuse` | 재기동·커넥터 재등록 없이 기존 환경 사용 |

옵션을 생략하면 `reuse`입니다. `first`·`start`는 일부 프로젝트 서비스가 이미 실행 중이면 자동 재시작하지 않고 멈춥니다. 필요한 서비스가 모두 실행 중인지, 일부만 기동된 상태인지 먼저 확인합니다. `.env`와 볼륨을 덮어쓰거나 삭제하는 초기화 절차는 포함하지 않습니다.

## 무엇을 실행하고 확인하나요?

환경 점검 뒤 **새 CASE_ID**를 만들고 결제 100,000원, 환불 20,000원 생성, 같은 환불 30,000원 정정, 삭제 순서로 진행합니다. 각 환불 변경 뒤 원천·Kafka·Bronze·파서·수집 대조와 실제 Parquet 내용을 확인합니다. 파일 경로만 출력하는 것과 파일 바이트를 읽어 확인하는 것을 구분합니다.

아래는 새 환불 키 하나의 기대값입니다. 전체 토픽 건수나 모든 파이프라인의 보장이 아닙니다.

| 변경 | 원천 현재 환불 | Kafka 레코드(누적) | Bronze 이력(누적) |
|---|---|---|---|
| 20,000원 생성 | 1행·20,000원 | 1건 | 1건 |
| 30,000원 정정 | 1행·30,000원 | 2건 | 2건 |
| 삭제 | 0행 | 4건 | 3건 |

삭제의 Kafka 4건은 c/u/d에 같은 키의 wire-null tombstone이 더해진 이 예제의 값입니다. DELETE 이벤트의 `after: null`과 tombstone의 value 전체가 null인 것은 다릅니다. Bronze는 tombstone을 제외합니다. 파일 수와 이력 행 수도 같다고 가정하지 않습니다.

### 마트까지 궁금할 때만

이미 기동된 환경에서 새 실행을 시작하며 다음 옵션을 추가할 수 있습니다.

```bash
./scripts/self-study.sh --environment reuse --with-marts
```

각 단계에서 Silver 처리와 dbt 모델·테스트, Gold 확인을 추가합니다. 새 주문의 순결제액 기대값은 결제 뒤 **100000 → 환불 생성 뒤 80000 → 정정 뒤 70000 → 삭제 뒤 100000**입니다. 주문일 기준 결제 성공액에서 환불 성공액을 뺀 값이며 회계상 매출을 뜻하지 않습니다.

최초 bootstrap도 기준 Silver·Gold/dbt를 준비합니다. 다만 **이번 새 사건의 단계별 마트 갱신은 `--with-marts`를 선택했을 때만** 실행합니다. 기본 실행으로 Gold까지 자동 반영됐다고 판단하지 않습니다. 이 옵션은 수업에서 다루지 않은 모델 구현을 새 과제로 추가하는 뜻이 아닙니다.

## 어디에서 결과를 읽나요?

기본 결과 폴더는 `artifacts/runs/self-study/<자동 CASE_ID>/`입니다.

- `report.md`: 기대값과 단계별 확인 결과를 사람이 읽는 보고서.
- `report.json`: 최종 상태·각 단계·실패 이유 등 구조화한 결과.
- `steps.json`: 어떤 단계까지 실행됐는지와 로그 위치.
- 순번이 붙은 단계 폴더: `stdout.txt`, `stderr.txt`, `result.json`과 조회한 원문 JSON.

환불 각 단계의 증거를 별도로 남깁니다. 결과가 `passed`인지, 기대값과 실제 행이 맞는지, 실제 파일 대조가 통과했는지 읽습니다. 로그가 생겼거나 컨테이너가 RUNNING이라는 사실만으로 데이터 검증이 끝난 것은 아닙니다.

`wait_observed_seconds`는 wait 명령 시작부터 첫 Bronze 관측까지입니다. 원천 commit부터의 전체 지연이나 고정 처리 시간을 증명하지 않습니다. 이 도우미는 한 공통 키의 기대 동작을 확인하며 모든 장애에서의 exactly-once·복구·SLA를 보장하지 않습니다.

다시 확인할 때는 기본 자동 CASE_ID를 사용합니다. 이미 사용한 키나 기존 결과 폴더는 재사용하지 않습니다. 필요하다면 `--case-id`로 아직 사용하지 않은 `s01-` 형식의 키, `--output-dir`로 새 폴더를 지정할 수 있지만 기본값으로도 실행할 수 있습니다.

## 멈췄다면 마지막 단계부터 확인하기

| 멈춘 곳 | 먼저 볼 것 |
|---|---|
| Docker·환경 점검 | 개인 Docker 실행 상태, Engine/Compose/Python 요건, 선택한 환경 모드 |
| 일부 서비스만 실행 중 | 서비스 상태와 마지막 기동 로그. 자동 재시작으로 덮어두지 않음 |
| Airflow가 실행 중 | 이 공통 실행과 주기 작업이 겹치는지 확인. 도우미가 자동 중지하지 않음 |
| 이미 사용한 키·결과 폴더 | 이전 증거를 보존하고 새 CASE_ID·새 결과 폴더 사용 |
| 변경이 보이지 않음 | `steps.json`의 마지막 단계와 해당 `stderr.txt`·원천/Kafka/Bronze 증거 |
| 실제 파일 대조 | 같은 키·조회 범위와 저장소·파일 읽기 오류, 해당 단계 로그 |

실행을 시작한 뒤 실패하면 확인된 단계와 실패 이유가 보고서에 남습니다. 기대값을 실측처럼 채우거나 중간 DML만 무작정 반복하지 않습니다. 원인을 확인한 뒤 새 키로 다시 실행합니다. 상태를 지우는 reset·볼륨 삭제나 DML 자동 재시도는 하지 않습니다.

환경은 자동 종료하지 않습니다. 끝나면 자신의 작업을 저장하고 필요할 때 다음 명령으로 savepoint를 남기며 중지합니다.

```bash
./scripts/stop.sh
```

실행 결과는 개인 설계의 참고 증거입니다. [3회차 설계 학습지](../labs/session03/design-worksheet.md)의 선택 이유·기대값·보류 질문과 연결해 정리하고, 제출 방법과 기한은 수업 공지를 따릅니다.
