## 그대로 채택하지 않은 표현

- 검토문의 “ingested_at과 조회 사이에 최소 한 checkpoint 주기”는 부정확하다. 처리 시점과 다음 checkpoint 완료·sink commit·조회 시점에 따라 달라진다. checkpoint 성공 후에도 Iceberg commit 실패를 별도로 확인해야 한다. [Iceberg 공식 문서](https://iceberg.apache.org/docs/latest/flink-writes/).
- 20000→30000 환불 정정과 순결제액 80000→70000은 수학적 충돌이 아니다. 문제는 과거 그림이 현재 수업 범위를 잘못 전달한 점이므로 이전 마트 시연 표기를 제거했다.
- 8회 스터디를 8주로 바꾸지 않았다. 후속 기능을 특정 회차에 모두 완성한다고 임의 확정하지 않는다.
- Raw 저장은 JSON 파싱과 현재 상태 구성을 분리하는 선택이다. 보존·접근 권한·스키마 처리 없이 무기한 재구축을 보장하는 기술로 설명하지 않는다.
- 개인 설계 25분에 DML·SELECT 전체까지 다시 요구하지 않았다. 명세·DDL·기대 이벤트를 수업 중, 나머지는 다음 회차 전 과제로 분리했다.

## 코드 검증 범위

기존 실제 리허설의 c/u/d 증거 세 세트에서 검증 함수와 12줄 요약의 이벤트 선택·위치·history·wait 미기록 처리를 확인했다. wait 시각 반환은 결정된 조회·시계로 별도 검사했다. 이런 기록 기반·모의 검증을 새 실측이라고 부르지 않는다. 새 맥미니 리허설 결과는 별도 기록에 연결한다.

자료 검토 도중 VM 여유 공간이 사전 기준(2GiB)에 미달해 실행을 중지했다. 원천·Kafka·Iceberg 볼륨을 지우지 않고 컨테이너가 참조하지 않는 이전 빌드 이미지만 정리한 뒤 preflight ready=true, 약 2.83GiB를 확인했다. 수업 전에는 다시 점검하며 5GiB 이상을 권장한다. 이미지 정리만으로 데이터 이력의 장기 공간 관리가 해결됐다고 판단하지 않는다.
